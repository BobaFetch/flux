# Plan m7 — Picker, Lua config, clipboard
Owner: Y'shtola / Date: 2026-10-03 / Status: active

## Goal
flux works as a daily driver: `+`/`*` registers talk to the system clipboard,
files and buffers open through a fast picker with Tab completion on the
command line, and startup behavior (options, colors, LSP servers, keymaps)
comes from a Lua config file. M0–M6 behavior stays green throughout.

## Scope
Strict sequence A → B → C (stages share engine/editor files, so no overlap).
Per-stage phase order: Lightning → Aerith → Tifa → Fina; Fina's approve gates
the next stage.

Stage A — Clipboard (`+`/`*` ↔ system clipboard):
- `"+y`, `"*y`, deletes into `+`/`*`, and puts from them round-trip with the
  system clipboard; unnamed register behavior unchanged.
- Write path: OSC 52 through the terminal output path. Read path: platform
  paste helper probed at runtime (macOS `pbpaste` verified on this machine;
  Linux helper confirmed on Linux during implementation), refreshed on
  focus-gained and before `+`/`*` puts.
- Deterministic tests via an env-driven fake clipboard provider.

Stage B — Picker + command-line Tab completion:
- File picker and buffer picker (prompt + match list + preview-less open).
- `<Tab>`/`<S-Tab>` completion on the command line for Ex commands, file
  paths, buffer names, option names (`:set`), and register names. Today Tab
  inserts a literal tab (`crates/flux-vim/src/engine.rs:804`); this is the
  planned M7 change.
- In-workspace fuzzy matcher (no new dependency); file traversal reuses the
  explorer patterns; picker UI reuses the float/popup infrastructure.

Stage C — Lua config + `:colorscheme` / `:highlight`:
- `init.lua` loaded at startup; minimal `flux` API: `flux.opt` (options),
  `flux.map` (non-recursive per-mode mappings), `flux.lsp` (server configs,
  superseding `FLUX_LSP_CONFIG` which stays as test override).
- `:colorscheme <name>` and `:highlight` (group inspection/override) with at
  least a built-in `default` and one alternate scheme.
- Lua runtime: mlua 0.12, features `lua54` + `vendored` (see D1).

## Non-goals
- Visual-block mode, command-line window (`q:`), autocmds, user commands,
  plugin loading/ecosystem (M8+ candidates).
- OSC 52 read queries; mouse support; swap files; M6 leftovers (inlay hints,
  lenses, `:clist`, `fuzzy` completeopt).
- Neovim plugin/API compatibility (README: flux has its own Lua API).
- No `gen` re-records unless a stage plan explicitly approves one.

## Approach
D1 — Lua via mlua 0.12 (`lua54` + `vendored`). Inspected docs.rs: mlua
0.12.1 is MIT-licensed, rust-version 1.88 (under the pinned 1.98), edition
2024, and ships `lua54`/`vendored` features. Rejected: system Lua (breaks
hermetic builds/CI), LuaJIT (unneeded; no nvim compat target). Lua 5.4 over
5.5 is a stability judgment; revisit any time (feature flip + re-verify).
D2 — Clipboard write is OSC 52 (`c` selection, base64 payload) per xterm
ctlseqs Ps=52; it works locally and over SSH with compliant terminals, needs
no new dependency, and follows the renderer's OSC 8 precedent. Reads use a
probed platform helper because there is no paste path today (no
bracketed-paste support anywhere in the tree).
D3 — The engine stays IO-free: Lightning defines Editor-side data slots (a
pending outbound clipboard write; an inbound refresh entry point); the binary
(Aerith) performs all terminal/process IO and drains the outbound slot each
frame (inbound refresh per Scope A).
Same split as LSP (engine state vs `servers.rs` processes).
D4 — Picker matching and base64 are small in-workspace implementations; no
new dependencies outside mlua, keeping `cargo deny` churn to one crate.
Exception (2026-10-05, `.sectorfive/decisions.md`): owner approved `ignore`
0.4.33 (flux-view) for F-01 gitignore-aware `:Files` only. No other new
dependency is approved by this exception.
D5 — Config path follows the repo's XDG pattern (`servers.rs`): prefer
`$XDG_CONFIG_HOME/flux/init.lua`, else `~/.config/flux/init.lua`; missing
file means stock behavior (no error).

## Steps
A1. Clipboard engine contract — Lightning — `crates/flux-view/src/registers.rs`,
`editor.rs`: `+`/`*` route through sync slots; `:registers` parity; no IO.
A2. Clipboard binary IO — Aerith — `crates/flux/src/main.rs`, new provider
module: OSC 52 emit, helper probing + reads, focus refresh, fake provider.
A3. Clipboard polish — Tifa — only if new user-facing messages need copy
review; else skipped with rationale in the completion report.
A4. Clipboard verify — Fina — fake-provider tests, baseline gates, manual
yank/paste checks; verdict gates Stage B.
B1. Picker + completion engine — Lightning — `flux-vim` cmdline paths
(`engine.rs`, `ex.rs`), new matcher + traversal in `flux-view`, picker state;
Tab contexts per Scope.
B2. Picker UI + wiring — Aerith — `flux-tui` rendering via float/popup
surfaces, prompt/list keys (`<Up>`/`<Down>`/`<CR>`/`<Esc>`, Tab cycle).
B3. Picker polish — Tifa — list hierarchy, spacing, highlight groups, copy.
B4. Picker verify — Fina — corpus/matcher tests, oracle additions if planned,
manual picker + completion checks; verdict gates Stage C.
C1. Lua runtime + config — Lightning — mlua dep (`lua54`, `vendored`),
config loading, `flux.opt`/`flux.map`/`flux.lsp`, `:colorscheme`/`:highlight`,
LSP config migration path. New-dependency approval is this plan.
C2. Startup wiring — Aerith — `main.rs` config load order (config before
`open_args`), error surfacing for a failing `init.lua` (message + continue
stock, never a crash).
C3. Config polish — Tifa — error/notice copy only; skipped if none.
C4. Full verify — Fina — fixture-config tests, `cargo deny check` (mandatory
for the new dep), full baseline, manual daily-driver pass; final verdict.

## Contracts touched
- `+`/`*` register semantics (internal-only today → system-synced); unnamed
  register untouched.
- New binary↔editor clipboard handoff (data slots, no IO in engine/view).
- Cmdline `<Tab>` behavior change (literal tab → completion; Neovim parity).
- New Lua API surface (`flux.opt`, `flux.map`, `flux.lsp`) — experimental,
  versioned by milestone; new `:colorscheme`/`:highlight` commands.
- New config-file path contract (XDG, §D5).
- New dependency: mlua 0.12 (+ `vendored` Lua build); `cargo deny` must pass.

## Validation Plan
Every stage: `cargo fmt --all --check`, `cargo clippy --workspace
--all-targets -- -D warnings`, `cargo test --workspace`, `cargo xtask indent
check`, `cargo xtask colors check` (oracle-check stays blocked per baseline;
recorded replay must pass). No new warnings.
- A: fake-provider round-trip tests (yank→read-back, external→put);
  manual: `"+yy` then paste into another app; copy outside then `"*p`;
  SSH/tmux spot check for OSC 52.
- B: matcher unit tests + picker open-file/buffer tests; manual: pickers over
  this repo, Tab through `:e`, `:b`, `:set`, `:ls` contexts (`:colorscheme`
  completion arrives with Stage C).
- C: fixture `init.lua` tests (options apply, maps apply, bad config warns +
  continues); `cargo deny check` mandatory; manual: daily-driver pass with a
  real config (options, colorscheme, LSP, maps).
Highest-risk validation: C — new native dependency plus brand-new API
semantics; build + deny + fixture tests must all pass on the pinned
toolchain before any follow-up work.

- No contract break outside this plan; no new deps outside mlua, except the

## Risks / Open Questions
- Terminal OSC 52 support varies (and can be disabled server-side per
  ctlseqs); mitigation: document, plus platform-helper reads stay independent.
- mlua build weight (vendored C) slows clean builds; mitigation: minimal
  features only (`lua54`, `vendored`), workspace-shared dep.
- `flux.map` engine semantics is the largest design surface in C; if review
  shows it ballooning, Y'shtola may split C and defer maps to M8 by plan
  amendment (not silently).
- Open questions: None. Init path, Lua version, matcher, and provider design
  were decided above from repo evidence; flag disagreements before `go`.

## Rollback
- Per stage: revert that stage's commit(s); stages are additive, so revert is
  clean. Clipboard with no provider degrades to today's internal registers;
  missing/bad `init.lua` degrades to stock behavior — both degradations are
  tested, not assumed.
